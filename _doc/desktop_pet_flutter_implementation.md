# Flutter 桌面宠物实现方案

> 编写日期：2026-09-16  
> 适用项目：`todo_manage`  
> 首要目标平台：Windows 10/11

## 当前实施状态

桌面宠物原型与独立任务气泡窗口已于 2026-09-16 完成：

- 应用以透明、无边框、置顶的宠物模式启动；
- 宠物窗口固定为 110 × 120，单击时创建或显示独立的任务气泡窗口；
- 气泡显示、刷新和关闭均不修改宠物窗口尺寸及坐标；
- 拖动宠物时，气泡通过 `onWindowMove`/`onWindowMoved` 事件与窗口通道实时跟随；拖动结束会同步刷新宠物位置缓存；
- 应用启动约 3 秒后预创建隐藏的气泡窗口（子窗口通过 `autoShow` 参数区分预创建与点击创建），首次点击不再经历 Flutter 引擎冷启动；
- 气泡窗口失去焦点时自动隐藏（`onWindowBlur`）；失焦瞬间若正被宠物点击，会在 350ms 内抑制随后的 toggle，避免"关了又弹回"；气泡内的关闭按钮已移除，关闭途径为失焦、再次单击宠物和打开主窗口；
- 气泡支持刷新、标记任务完成和打开完整任务列表；
- 双击宠物可以切换到现有 Todo 主窗口；
- 主窗口最小化或关闭时返回宠物模式；
- 托盘菜单支持显示主窗口、显示宠物和退出；
- 增加今日未完成任务的专用 DAO 查询；
- 修复数据库父目录未创建和 DTO 分类名称异步填充问题；
- 已生成并接入透明背景的拟物风格记事本素材 `images/desktop_pet.png`。

当前版本采用“宠物/主界面根窗口 + 独立气泡子窗口”的双窗口结构。主界面仍由根窗口从宠物模式切换而来；任务气泡由 `desktop_multi_window` 创建为独立 Flutter Engine，并通过窗口通道与根窗口通信。

## 1. 目标

在现有 Todo 应用中增加一个常驻桌面的宠物功能：

- 宠物以透明、无边框的小窗口显示；
- 宠物窗口始终置顶，不出现在任务栏；
- 用户可以拖动宠物并保存其位置；
- 单击宠物时显示“当天未完成任务”气泡；
- 再次单击、点击关闭按钮或失去焦点时收起气泡；
- 双击宠物时显示并聚焦现有 Todo 主窗口；
- 关闭或最小化主窗口时，宠物继续运行；
- 托盘菜单可以显示主窗口、显示/隐藏宠物和退出应用。

非目标：第一版不实现桌面自由行走、重力碰撞、语音、联网对话和复杂 AI 能力。

## 2. 推荐架构

最终方案采用“双窗口 + 单进程”结构：

```text
todo_manage 进程
├── 根窗口 Root Window
│   ├── 宠物模式：DesktopPetPage（固定 110 × 120）
│   └── 主界面模式：MainPage
├── 气泡窗口 Task Bubble Window
│   └── TaskBubblePage（独立 Flutter Engine）
├── TaskBubbleWindowService
│   ├── 创建、显示、隐藏和定位气泡
│   └── 转发刷新、关闭和打开主界面命令
├── TodayTaskService
│   └── 查询当天未完成任务
├── AppDatabase / Drift
└── TrayController
```

选择双窗口的原因：

- 双击后主窗口出现时，宠物仍能留在桌面；
- 主窗口可以保持正常标题栏和任务栏行为；
- 宠物窗口可以独立设置透明、无边框、置顶和固定尺寸；
- 不需要频繁把同一个窗口在“宠物模式”和“主界面模式”之间改造。

多窗口候选采用 `desktop_multi_window`。该插件支持 Windows、Linux 和 macOS，并提供窗口控制及跨窗口通信能力。引入前应先做一个最小验证，确认它与项目当前的 Flutter、`window_manager`、`tray_manager` 和单实例插件兼容。

参考：

- <https://pub.dev/packages/desktop_multi_window>
- <https://pub.dev/documentation/window_manager/latest/window_manager/WindowManager-class.html>

## 3. 过渡方案

正式拆成双窗口之前，可以先实现“单窗口宠物模式”验证关键能力：

```text
同一个窗口
├── 宠物模式：透明、小尺寸、无边框、置顶
└── 主窗口模式：普通尺寸、标题栏、显示 MainPage
```

单窗口版适合验证：

- Windows 透明背景是否正常；
- 宠物动画资源是否合适；
- 单击、双击和拖动是否冲突；
- 气泡尺寸和任务展示效果；
- 高 DPI 和多显示器行为。

它不满足“主窗口打开时宠物仍然存在”，因此只作为低风险原型，不作为最终架构。

## 4. 窗口设计

### 4.1 主窗口

沿用现有 `MainPage`，保留普通窗口外观。

建议行为：

- 双击宠物：恢复、显示并聚焦主窗口；
- 托盘“显示窗口”：恢复并聚焦主窗口；
- 点击主窗口关闭按钮：隐藏主窗口，不退出进程；
- 托盘“退出”：关闭所有窗口、数据库连接和托盘图标后退出。

当前项目的关闭事件会询问用户并直接销毁窗口。增加宠物后，应明确区分“隐藏主窗口”和“退出整个应用”。

### 4.2 宠物窗口

建议初始属性：

| 属性 | 建议值 |
| --- | --- |
| 大小 | 110 × 120 逻辑像素 |
| 背景 | 完全透明 |
| 标题栏 | 隐藏 |
| 是否置顶 | 是，可在设置中关闭 |
| 是否显示在任务栏 | 否 |
| 是否可缩放 | 否 |
| 是否可最大化/最小化 | 否 |
| 初始位置 | 主显示器右下角、任务栏上方 |
| 窗口阴影 | 关闭 |

`window_manager` 已提供 `setAlwaysOnTop`、`setAsFrameless`、`setBackgroundColor`、`setBounds`、`setSkipTaskbar` 和 `startDragging` 等能力。

### 4.3 气泡

当前实现将气泡放在第二个独立窗口内。宠物窗口从启动到单击前后始终保持 110 × 120，不再通过扩大窗口容纳气泡，因此不会因尺寸变化和锚点换算产生位置偏移。

```text
┌──────────────────────────────┐
│ 今日未完成                 3 │
├──────────────────────────────┤
│ ○ 10:00 完成项目文档         │
│ ○ 15:30 处理反馈             │
│ ○ 今日   提交版本            │
│                              │
│             查看全部 →       │
└──────────────────────────────┘
                 ▼
                宠物
```

气泡建议限制最多显示 5 条任务。超过 5 条时显示“还有 N 条”，点击“查看全部”打开主窗口。

气泡每次显示前根据宠物窗口当前位置计算自身位置；拖动宠物后再次打开气泡，会重新对齐到宠物上方。Windows Runner 已按插件要求为子窗口 Flutter Engine 注册 `window_manager`、SQLite 等插件。

## 5. 交互设计

### 5.1 单击与双击

宠物组件使用 `GestureDetector`：

```dart
GestureDetector(
  onTap: toggleTaskBubble,
  onDoubleTap: showMainWindow,
  child: PetView(),
)
```

Flutter 的手势识别器会协调单击和双击。双击成立前，单击回调会等待双击判定结束，因此不应另外立即执行原生鼠标单击逻辑。

### 5.2 拖动

推荐交互：

- 鼠标按住宠物非按钮区域并移动：调用 `windowManager.startDragging()`；
- 移动结束：读取窗口坐标并保存；
- 下次启动：恢复保存的位置；
- 如果保存位置已经落在所有显示器之外：回退到主显示器右下角。

单击、双击和拖动可能互相竞争。实现时应设置一个最小移动阈值，拖动发生后不再触发单击。

### 5.3 气泡关闭

建议支持：

- 再次单击宠物；
- 点击气泡关闭按钮；
- 按 Esc；
- 主窗口打开；
- 可选：宠物窗口失去焦点后自动收起。

不建议第一版仅依赖“点击窗口外部关闭”，因为透明窗口和多显示器环境下的焦点行为需要额外验证。

## 6. 当天任务定义

“今日未完成”气泡当前的筛选条件为：

```text
deadlineTime < 当前时间
AND status != FINISHED
```

即所有截止时间已过但尚未完成的任务（包含更早的逾期任务）。没有截止时间的待办不进入列表，避免气泡无限增长。

查询结果按创建时间升序排列，最多显示 `limit`（默认 5）条。跨天时以查询时刻为准，气泡不会自动刷新。

DAO 建议新增明确的方法，而不是继续传递松散的 Map 参数：

```dart
Future<List<TodoThingDTO>> findTodayUnfinished({
  required DateTime day,
  int limit = 5,
});
```

日期边界应在 Dart 层生成本地时间的“当天开始”和“次日开始”，不要通过格式化后的字符串比较。

## 7. 数据与窗口通信

双窗口插件可能为不同窗口创建独立 Flutter Engine/Isolate。不要依赖 Dart 静态单例在两个窗口间共享状态。

推荐职责：

- 主窗口负责完整 Todo 编辑；
- 宠物窗口只读取今日任务；
- 保存、删除或状态变化后，通过窗口通道发送 `tasksChanged`；
- 宠物窗口收到消息后重新查询数据；
- 宠物双击后发送 `showMainWindow` 命令。

消息协议保持简单：

```text
showMainWindow
hideMainWindow
tasksChanged
refreshTodayTasks
shutdown
```

数据库方面有两种方式：

### 方案 A：两个窗口分别打开 SQLite

优点是实现直接；缺点是必须验证并发连接、写入锁和插件在子窗口中的注册情况。

### 方案 B：主窗口持有数据库，宠物通过窗口通道请求数据

优点是数据库连接集中；缺点是通信协议更复杂，主窗口 Engine 必须始终存活。

第一版建议使用方案 A，但宠物窗口只执行查询。若测试发现子窗口插件注册或数据库锁问题，再切换到方案 B。

在进入多窗口开发前，应先修复当前 `TodoThingDTOMapper` 中未等待的异步分类增强，避免气泡获得未完整填充的数据。

## 8. 模块拆分建议

建议新增以下目录和文件：

```text
lib/
├── app/
│   ├── app_bootstrap.dart
│   └── window_role.dart
├── desktop_pet/
│   ├── pet_app.dart
│   ├── pet_window_controller.dart
│   ├── pet_state.dart
│   ├── pet_view.dart
│   ├── pet_animation_controller.dart
│   └── today_task_bubble.dart
├── service/
│   ├── today_task_service.dart
│   ├── window_coordinator.dart
│   └── app_preferences.dart
├── widget/
│   └── ...现有界面
└── main.dart
```

职责说明：

- `AppBootstrap`：识别当前窗口角色并初始化必要插件；
- `WindowRole`：区分主窗口和宠物窗口；
- `WindowCoordinator`：封装窗口创建、显示、隐藏和通信；
- `PetWindowController`：配置宠物窗口属性和位置；
- `PetState`：管理待机、气泡展开、拖动等状态；
- `TodayTaskService`：封装今日未完成任务查询；
- `AppPreferences`：保存宠物位置、置顶开关、气泡设置等。

不要继续把所有初始化逻辑堆积在 `main.dart` 或静态配置类中。

## 9. 宠物动画

第一版建议使用透明 PNG 序列帧或精灵图，避免一开始引入复杂动画运行时。

建议状态：

```text
idle       待机循环
hover      鼠标悬停
dragging   被拖动
notifying  有今日任务或逾期任务
sleeping   长时间无操作
```

动画资源要求：

- 透明背景；
- 每帧尺寸一致；
- 明确帧率，例如 8～12 FPS；
- 控制资源大小，避免常驻应用持续高 CPU/GPU 占用；
- 宠物实际可点击区域尽量接近窗口尺寸。

若使用 GIF，状态切换和逐帧控制较弱；若后续需要复杂状态，建议使用精灵图控制器、Rive 或 Lottie。

## 10. 系统托盘调整

托盘菜单建议调整为：

```text
显示 Todo 窗口
显示/隐藏桌面宠物
宠物始终置顶 ✓
----------------
退出
```

“退出”必须是真正终止整个应用的唯一明确入口之一。关闭主窗口只隐藏主窗口，不销毁宠物窗口。

现有 `TrayConfiguration` 和 `TrayEventListener` 应改成持有实例的控制器，并在应用退出时移除 listener、销毁托盘图标和关闭数据库。

## 11. Windows 特殊问题

### 11.1 透明区域鼠标拦截

Flutter 窗口本质上仍是矩形原生窗口。即使背景透明，矩形内的透明部分也可能拦截下方应用的鼠标事件。

处理顺序：

1. 第一版让宠物窗口尺寸贴近宠物素材；
2. 验证当前 `window_manager` 和 Windows Runner 的透明区域行为；
3. 非交互状态可使用 `setIgnoreMouseEvents(true, forward: true)`，但它作用于整个窗口；
4. 若需要逐像素点击区域，在 Windows Runner 中通过 `WM_NCHITTEST` 和 Alpha 信息实现原生命中测试。

### 11.2 高 DPI 与多显示器

必须验证：

- 100%、125%、150%、200% 缩放；
- 主副显示器缩放比例不同；
- 宠物跨显示器拖动；
- 拔掉显示器后保存位置失效；
- 任务栏位于屏幕左侧、右侧或顶部。

窗口位置持久化时要明确使用逻辑坐标还是物理像素，并统一转换。

### 11.3 全屏应用

“始终置顶”不代表一定应覆盖全屏游戏或演示。建议增加设置：

- 普通置顶；
- 全屏应用出现时自动隐藏；
- 永不置顶。

第一版可以只实现普通置顶，并记录全屏场景为后续优化项。

- 修复数据库父目录创建；

- 明确关闭主窗口与退出应用的区别。

- 配置透明、无边框、置顶的小窗口；
- 显示静态宠物素材；
- 实现拖动、单击气泡和双击主界面；
- 验证 Windows 10/11、高 DPI 和鼠标行为。

目标：确认技术链路可行，不追求最终代码结构。

### 阶段 2：双窗口

- 引入并验证多窗口插件；
- 拆分主窗口和宠物窗口入口；

- Todo 数据变化后通知宠物刷新。

第一版气泡中建议只读展示；直接勾选完成可在后续加入，以降低多窗口写数据库的风险。

- 增加宠物动画状态机；

## 13. 测试计划

### 自动化测试

- `findTodayUnfinished` 日期边界测试；
- 已完成、未完成、已逾期和无截止时间过滤测试；
- 气泡状态切换测试；
- 窗口消息协议序列化测试；
- 宠物设置和位置恢复测试。

### 手工验证

- 单击只打开一次气泡；
- 双击不残留气泡，并打开主窗口；
- 拖动不会误触单击；
- 主窗口关闭后宠物仍存在；
- 托盘退出后不残留进程；
- 透明区域不会大面积阻挡鼠标；
- 多显示器和不同缩放比例下位置正确；
- 当天跨越 00:00 后任务能够刷新；
- 数据库写入期间宠物查询不会报锁错误。

## 14. 验收标准

第一版完成应满足：

1. 应用启动后显示宠物，宠物不出现在任务栏；
2. 宠物保持置顶且能够拖动；
3. 单击显示当天未完成任务，空列表时显示明确空状态；
4. 双击显示并聚焦 Todo 主窗口；
5. 主窗口与宠物可以同时存在；
6. 关闭主窗口不会退出宠物；
7. 托盘“退出”能够完整结束进程；
8. 重启后能恢复宠物位置；
9. Windows 10/11 和常见 DPI 下没有明显错位；
10. 静置时 CPU 占用保持较低，动画没有持续异常重绘。

## 15. 主要风险与决策点

| 风险/决策 | 建议 |
| --- | --- |
| 多窗口插件兼容性 | 在正式重构前完成最小技术验证 |
| 子窗口插件注册 | 验证 Drift、path_provider、window_manager 是否都能正常使用 |
| SQLite 多连接 | 宠物先只读，并增加并发读写测试 |
| 透明区域挡鼠标 | 缩小窗口范围，必要时增加 Windows 原生命中测试 |
| 动画常驻资源占用 | 限制帧率，窗口隐藏时暂停动画 |
| 单击/双击/拖动冲突 | 统一由宠物手势控制器管理 |
| 跨平台诉求 | 第一版明确只保证 Windows，稳定后再抽象平台能力 |

## 16. 推荐结论

现有项目继续使用 Flutter 实现桌面宠物是合理的。推荐先完成单窗口原型验证透明和鼠标行为，再落地“宠物窗口常驻 + Todo 主窗口按需显示”的双窗口架构。

第一版应把范围控制在窗口、今日任务气泡、拖动、托盘和基础待机动画。逐像素穿透、桌面行走和复杂动画属于后续原生增强，不应阻塞基础功能上线。
